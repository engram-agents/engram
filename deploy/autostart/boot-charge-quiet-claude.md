The pattern must exclude the session's own argv — this charge text quotes both monitor names and this very pgrep pattern, so an unanchored match (e.g. bare `forum-(mention|updates)-monitor`) always matches the booting session itself and can never report a dead monitor as dead; anchoring on the process name (`^bash`) is what makes the check a real verification instead of a tautology. Do not anchor the pattern's tail on `\.sh$` either — the updates monitor's argv ends `--kinds dm,baton`, so an end-anchor reports a live monitor as dead. **And pgrep is not sufficient: it proves a process exists, not that its output reaches you.** A monitor armed as a detached background process (`nohup … &`) instead of through the Monitor tool runs correctly, detects everything, and writes to a file nothing reads — and `pgrep` returns the same count either way. Check the stdout target of each matched pid: on Linux `_PIDS="$(pgrep -u "$USER" -f '^([^[:space:]]*/)?bash[[:space:]]+[^[:space:]]*forum-(mention|updates)-monitor\.sh')"; if [ -z "$_PIDS" ]; then echo "NO monitor processes matched -- this is a FAILURE, not a pass"; else for pid in $_PIDS; do readlink /proc/$pid/fd/1; done; fi` — each line must **begin** `socket:` for every pid (the bracketed inode number varies every run, so do not compare it literally) — a `/tmp/….log` or any other file path means that monitor is a dead end. **macOS has no `/proc`**, so a Darwin seat runs the matching loop instead: `_PIDS="$(pgrep -u "$USER" -f '^([^[:space:]]*/)?bash[[:space:]]+[^[:space:]]*forum-(mention|updates)-monitor\.sh')"; if [ -z "$_PIDS" ]; then echo "NO monitor processes matched -- this is a FAILURE, not a pass"; else for pid in $_PIDS; do lsof -a -p "$pid" -d 1; done; fi` and looks for `TYPE unix` / socket rather than a regular file path; running the Linux form there does NOT fail loudly, and **the tell is the line count: if the loop prints fewer lines than you have pids — or none at all — you are on the wrong branch or a monitor is unreadable, and the clean-looking result IS the failure.** Mechanism, measured on Darwin 25.6.0: `readlink /proc/$pid/fd/1` yields empty stdout and exit 1 for every pid, and this charge never checks that status, so the loop emits nothing at all — which against "each line must begin `socket:` for every pid" inspects as clean.
