Check the stdout target of each matched pid: on Linux `_PIDS="$(pgrep -u "$USER" -f '^([^[:space:]]*/)?bash[[:space:]]+[^[:space:]]*forum-(mention|updates)-monitor\.sh')"; if [ -z "$_PIDS" ]; then echo "NO monitor processes matched -- this is a FAILURE, not a pass"; else for pid in $_PIDS; do _T="$(readlink /proc/$pid/fd/1)" || { echo "pid $pid: stdout target UNREADABLE -- FAILURE, not a pass"; continue; }; case "$_T" in socket:*) echo "pid $pid: $_T" ;; *) echo "pid $pid: $_T -- NOT a socket, this monitor is a dead end" ;; esac; done; fi` — this loop is built to print exactly one line per pid in every outcome (live, unreadable, or non-socket), so **count the printed lines against `$_PIDS`: fewer lines than pids means the check itself broke, not that the missing pid passed.** Each pid's own line must carry `socket:` right after the `pid <N>:` label (the bracketed inode number varies every run, so this is a prefix check on that segment, not an equality check) — `UNREADABLE` or a file path there means that monitor is a dead end. **Do not judge the loop by its own exit status.** A `for` loop's exit status is the *last* iteration's only, so on the identical set of failures the check reads exit 0 or exit 1 purely by where the dead pid falls in `pgrep`'s pid-ascending output — measured directly on Linux 6.6.87.2/WSL2: a live pid's `readlink` exits 0 with `socket:[inode]`; done`, no capture) drops that pid's line outright either way, 2 lines for 3 pids. **macOS has no `/proc`**, so a Darwin seat runs the matching loop instead: `_PIDS="$(pgrep -u "$USER" -f '^([^[:space:]]*/)?bash[[:space:]]+[^[:space:]]*forum-(mention|updates)-monitor\.sh')";
